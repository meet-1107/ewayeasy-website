1. Environment files: do you need any?

No extra env file is needed. Everything the live site needs is already in the repository, in .env.production. That file is committed on purpose because every value in it is public (it already appears in the website's pages).

Variable (in .env.production)What it doesSecret?
NEXT_PUBLIC_SITE_URLhttps://ewayeasy.in, used for canonical links, sitemaps and IndexNowNo
NEXT_PUBLIC_PLAY_STORE_URLGoogle Play link for the app buttonsNo
NEXT_PUBLIC_SUPPORT_EMAILEmail shown on the contact pageNo
NEXT_PUBLIC_WEB3FORMS_KEYLets the contact form email you through Web3FormsNo: public by design; it can only send to your own address
NEXT_PUBLIC_CLARITY_IDMicrosoft Clarity analyticsNo
NEXT_PUBLIC_GA_ID, NEXT_PUBLIC_GSC_VERIFICATIONOptional, currently emptyNo
  • .env.example is only a template that lists the variables. It is not used by the build.
  • If you ever need a private value on one computer only, put it in .env.local. That file is ignored by Git and never uploaded.
  • Never put passwords, Firebase login tokens or bank details in any env file that is committed.
  • To change the contact-form key: create a new key at web3forms.com, replace it in .env.production, commit and deploy.

Other files that make deploy work (all in the repository):

FilePurpose
.firebasercPoints to the Firebase project ewayeasy-website
firebase.jsonHosting settings and redirects
public/2f36bf4493a7d9b2e030dd97300cb7b3.txtIndexNow key (proves to Bing that you own the site). Do not delete.
.indexnow-state.jsonRemembers which pages were already sent to IndexNow, so only changed pages are sent next time. Commit it after each deploy.

2. What a GitHub ZIP contains, and what it does not

Included in the ZIPNot included
All source code, content, images, .env.production, .firebaserc, firebase.json, the IndexNow key file, scripts and docs Git history: you cannot commit or push from a plain ZIP folder (fix in section 4B).
node_modules: recreated with npm install.
.next and out: recreated by the build.
Your Firebase login and GitHub login: you sign in once per computer.
Recommendation: use git clone instead of the ZIP. A clone has the history, so commit, push and pull work at once.

3. Install the tools (one time per computer)

  1. Node.js 22 LTS or newer from nodejs.org (this project is built with Node 24; Node 20 or newer works). Check: node -v
  2. Git from git-scm.com. Check: git --version
  3. Firebase CLI: nothing to install. The project runs it with npx firebase-tools.
  4. An internet connection during builds: the build downloads the Google Fonts it uses.
  5. Optional: Google Chrome, only for the script that captures blog cover images.

Set your name for commits (once):

git config --global user.name "meet-1107"
git config --global user.email "your-github-email@example.com"

4. Get the code

A. Clone (recommended)

cd "C:\Users\web apps"
git clone https://github.com/meet-1107/ewayeasy-website.git eway-easy-website
cd eway-easy-website
npm install

B. You already downloaded the ZIP

Unzip it (GitHub names the folder ewayeasy-website-main; you can rename it). Then connect it to GitHub so commit and push work:

cd "C:\path\to\ewayeasy-website-main"
git init
git remote add origin https://github.com/meet-1107/ewayeasy-website.git
git fetch origin
git checkout -f -B main origin/main
npm install

git checkout -f makes the folder match GitHub exactly. If you edited files in the ZIP folder before this step, copy them somewhere safe first and put them back afterwards.

6. Check before you publish

npm run build
npm test
npm run check:links
npm run check:seo
  • npm test: about 227 automated tests (calculators, templates, PIN distances, content rules).
  • check:links: finds broken internal links.
  • check:seo: every page has one H1, a canonical link, and a unique title and description.

Run the two check scripts after npm run build, because they read the built out/ folder.

7. Commit and push to GitHub

git pull
git status
git add -A
git commit -m "Describe what you changed"
git push origin main
  • Always git pull first, so you build on the latest version.
  • The first push on a new computer opens a GitHub sign-in window (Git Credential Manager). Sign in as meet-1107.
  • If a sign-in window does not appear, create a Personal Access Token on GitHub (Settings → Developer settings → Tokens) and paste it when Git asks for a password.
  • Check git status before git add -A: never commit .env.local or personal files.

8. Deploy to ewayeasy.in (Firebase)

First time on a computer

npx firebase-tools login

Sign in with the Google account that owns the Firebase project ewayeasy-website. Check access with:

npx firebase-tools projects:list

Every deploy

cd "C:\Users\web apps\eway-easy-website"
npm run deploy:firebase

This single command:

  1. builds the site into out/;
  2. uploads out/ to Firebase Hosting (live in about a minute);
  3. sends the new or changed page addresses to search engines through IndexNow and updates .indexnow-state.json.

Then commit the updated IndexNow state:

git add .indexnow-state.json
git commit -m "IndexNow state after deploy"
git push origin main

Check it is live: open https://ewayeasy.in in a private window and look for your change. To roll back, open Firebase console → Hosting → Release history and restore the previous version.

Low-memory computer? Build with one worker:
PowerShell: $env:BUILD_CPUS='1'; npm run deploy:firebase
Command Prompt: set BUILD_CPUS=1 && npm run deploy:firebase

9. After deploying: search engines

  • Bing and other IndexNow engines are told automatically by the deploy command.
  • Google Search Console: the sitemap https://ewayeasy.in/sitemap.xml is already submitted. For an important new or changed page, use URL Inspection → Request indexing.
  • Bing Webmaster Tools: optional manual submission with docs/all-urls.txt (list of all pages).

11. Troubleshooting

ProblemFix
Failed to fetch font / network error during buildThe build downloads Google Fonts. Check the internet connection and run the command again.
ENOENT ... rename ... 500.htmlA dev server was running during the build. Stop it, delete the .next folder, build again.
Build runs out of memory or freezesUse BUILD_CPUS=1 (section 8).
firebase: command not foundUse npx firebase-tools ... as written in this guide.
Firebase "permission denied" or "not authorized"Run npx firebase-tools login with the account that owns ewayeasy-website.
indexnow: missing NEXT_PUBLIC_SITE_URL or public/<key>.txt.env.production or the key file is missing. Restore them from GitHub.
Push rejected ("fetch first")Run git pull, then git push origin main again.
"Port already in use"Close the other server, or run npx next dev -p 3001.
Tests or checks failRead the first failing line; it names the file and the problem. Fix it before deploying.
